# Задание Codex № 10 — один визуальный источник (дополнение к № 09)

**Скопируйте текст ниже целиком в Codex.** Это дополнение к заданию № 09,
а не замена: этапы A–E остаются. Здесь добавляется предусловие, без
которого «обновилось в системе — обновилось в прототипе» невозможно
физически.

---

## Что измерено

PO поставил задачу: прототип должен **брать** компоненты из дизайн-системы,
и обновление компонента в системе должно приходить в прототип само, без
правок кода. Прежде чем строить механизм, исполнитель измерил, что мешает.

Мешает не структура. Мешает **словарь**:

| | Витрина | `tokens.css` |
|---|---:|---:|
| объявлено токенов | 28 | 199 |
| **общих имён** | **0** | **0** |

Витрина **подключает** `tokens.css` строкой 2 — и не использует из него ни
одного имени. Она объявляет собственные `--orange`, `--black`, `--b-hair`,
`--b-def` и красит всё ими. Система в это же время оперирует
`--color-brand-accent`, `--color-text-primary`, `--border-hairline`.

Следствия, которые из этого выводятся, а не предполагаются:

- **`<link>` на токены декоративен.** Файл грузится и не влияет ни на что.
- **Ремедиация системы не доходит до витрины по построению.** Кнопка витрины
  осталась `#FD5E00` (3,10:1 с белым) не потому, что кто-то забыл, а потому
  что `--orange` — другая сущность, чем `--color-action-primary-bg`, который
  аудит исправил на `#C94700` (4,79:1). Изменение одного никогда не
  затронет другое.
- **Никакой общий файл стилей не поможет**, пока классы ссылаются на
  `--orange`, а приложение — на `--color-action-primary-bg`. Это не разные
  значения одного токена, это разные токены.

## Что нужно сделать — два этапа, оба предшествуют A–E задания № 09

### Этап 0. Один словарь

Перевести витрину на имена системы. Для каждого из 28 частных токенов:

1. **Есть системный эквивалент** — заменить ссылку. `--orange` →
   `--color-brand-accent`, `--b-hair` → `--border-hairline`, и так далее.
   Соответствие устанавливаешь ты; таблицу «частное имя → системное имя →
   почему именно оно» приложи к отчёту, она понадобится при сверке.
2. **Системного эквивалента нет** — добавить токен в `tokens.css` с пометкой
   `[provisional]` и обоснованием. Придумывать значение запрещено (R-25):
   если значение неоткуда взять, запись идёт в `adr-drafts-260806.md`, а
   витрина временно ссылается на ближайший системный токен с комментарием.
3. **Значение витрины противоречит системному** — правы токены, они прошли
   аудит позже (витрина датирована 04.08, ремедиация 05.08). Расхождение
   назови в отчёте: это не молчаливая замена, а зафиксированное решение.

Блок `:root` внутри `<style>` витрины после этого этапа **пуст или
отсутствует**: значения живут в одном файле.

### Этап 1. Один файл классов

Извлечь `<style>` витрины в **`design-system/components.css`**:

- витрина подключает его `<link>`, собственного `<style>` больше не имеет
  (кроме, при необходимости, `@font-face` — но лучше и его туда же);
- классы именуются с префиксом **`a3-`**: `.a3-button`, `.a3-driver-row`.
  Нынешние `.btn`, `.drv`, `.okc-tile` слишком общие: приложение подключит
  этот файл рядом с Tailwind, и `.btn` столкнётся с чем угодно;
- **каждая группа классов несёт свой `DC-NN`** — это тот же ключ
  трассируемости, что этап A задания № 09, только теперь он нужен и в CSS:
  комментарием `/* DC-44 */` над группой;
- **у каждого класса, требующего определённой разметки, структура описана
  комментарием.** Это главный риск всей затеи: класс, написанный под
  разметку витрины, молча не сработает на другой вложенности. Приложение
  обязано знать, какую структуру повторять.

После этого этапа приложение подключает `components.css` одной строкой, и
любая правка в нём приходит в прототип без изменения кода — то, чего просит
PO.

## Чего делать НЕ нужно

- **Не переписывай визуальный язык.** Пропорции, плотность и композиция
  витрины — то ценное, ради чего её сохранили. Задача — сменить имена и
  место хранения, а не внешний вид.
- **Не трогай `src/**`.** Приложение переводит на новые классы исполнитель;
  порядок работ согласован, твоя часть — предусловие.
- Порядок важен: **этап 0 строго раньше этапа 1.** Извлечь классы, которые
  ссылаются на частные токены, значит зафиксировать расхождение в отдельном
  файле и сделать его труднее заметным.

## Формат отчёта

Дополнить `docs/audit/verdicts/codex-design-system-260806.md` разделом
«Единый визуальный источник». Первая строка раздела:

```
ЭТАП 0/1: частных токенов переведено N из 28 · новых provisional-токенов M · расхождений значений K · классов извлечено C
```

Обязательно приложить таблицу соответствия имён и список классов, для
которых структура разметки является обязательной, — по ней исполнитель
будет приводить компоненты в соответствие.
