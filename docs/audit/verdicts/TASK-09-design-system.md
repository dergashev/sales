## Что изменилось: ты теперь автор системы, а не только её аудитор

PO разделил работу на два потока. Ты доводишь дизайн-систему, второй инструмент параллельно ведёт прототип. **`design-system/**` переходит в твою зону записи целиком, включая `tokens.css`.** Взамен твою работу теперь проверяет второй инструмент — самопроверка не считается проверкой ни для одной стороны.

Два ограничения, которые в новой роли важнее прежних:

1. **`R-25`: значение, которого норматив не даёт, не выдумывается.** Ты вправе предложить значение с пометкой `[provisional]` и обоснованием. Объявить его принятым — не вправе: из 51 открытого ADR семнадцать записей не имеют значения вовсе (`adr-blocking.md` §6a), и пока владелец дизайна их не примет, ни один компонент не выходит из `alpha` (`TOKEN-005`). Предложение без пометки является скрытым решением.
2. **Токены: добавление свободно, переименование и удаление — только с записью в отчёте.** Реализация ссылается на имена токенов; проверка `TOKEN-EXISTS` в `npm run verify` требует, чтобы каждый `var(--x)` из `src/` и `tailwind.config.ts` существовал в `tokens.css`. Она уже нашла три сломанные ссылки в первый прогон — не создавай новых молча.

## Порядок работ

### A. Трассируемость — делать первым, иначе остальное не проверяется

Три представления одного компонента **не связаны идентификатором**: контракт зовёт его `EstimateUncertaintyBadge`, код — `UncertaintyBadge`, витрина — классом `.iv-band`. Две машинные сверки подряд дали ложный результат именно поэтому.

Введи ключ: **каждый блок витрины несёт `data-dc="NN"`** на корне (у контрактов номер уже есть). Тогда покрытие «контракт ↔ витрина» проверяется скриптом. Скрипт писать не нужно — это зона второго инструмента; тебе нужен ключ и отчёт о том, какие контракты образца не получили и почему.

### B. Расхождение витрины с нормативом

Витрина датирована **04.08**, ремедиация аудита прошла **05.08**, и витрина местами старее норматива. Одно расхождение проверено численно и является блокирующим:

| Что | Витрина | `tokens.css` | Норма |
|---|---|---|---|
| Заливка `.btn` | `#FD5E00` + белый текст = **3,10:1** | `#C94700` + белый = **4,79:1** | 4,5:1 |

Витрина не является источником для цвета: где она противоречит `tokens.css`, правы токены — они прошли аудит позже. **Найди остальные такие расхождения сам**: одно проверено, полный список — нет. Правило 4 проверено отдельно и нарушений не имеет (пятнадцать `border-radius` — все `50%` на идеальных кругах при глобальном `* { border-radius: 0 !important }`).

### C. Недостающие образцы

Для четырёх контрактов из §A и пяти компонентов прототипа без образца — собрать блоки витрины по их контрактам. Тексты и числа берутся из фикстуры и контрактов; собственных значений у витрины нет.

### D. Контракты против реализации

Реализация прототипа за 05–06.08 местами уточнила контракт, местами разошлась с ним. Расхождения, найденные вторым инструментом при сверке, — в реестре §3 и в вердикте `codex-prototype-recheck-260806.md`. По каждому реши: **контракт прав и код чинят, или код прав и контракт уточняется**. Молчаливое согласие не годится ни в ту, ни в другую сторону — решение с обоснованием пиши в отчёт.

Отдельно посмотри `components-core.md`: 22 контракта примитивов против того, что собрано. `SegmentedControl`, `RadioCardGroup`, `Switch`, `Tabs`, `Button`, `NumericInput`, `Skeleton` реализованы; `Tooltip`, `Dialog`, `Link`, `Slider`, `SaveStatus`, `KeyboardShortcutService`, `DataTable`, `DisclosureRow`, `Badge`, `Card`, `Chip`, `FormField`, `Textarea` — нет. Часть из них блокирована открытыми ADR-токенами, часть — нет. **Раздели эти два множества**: заблокированное ждёт владельца, незаблокированное можно специфицировать до конца.

### E. ADR — предложения, не решения

`adr-drafts-260806.md` содержит пять внесённых приближений и список записей без значений. Дополни его: для каждой открытой записи §6a дай **предложение с обоснованием и проверкой контраста, где применимо**, помеченное `[provisional]`. Владелец решает; ты готовишь решение.

- **Не трогай `src/**`, `tools/**`, `docs/**` кроме своей зоны** — там параллельно работает второй инструмент, и конфликт правок дороже любой находки. Нужное там называй адресом `файл:строка` в отчёте.
