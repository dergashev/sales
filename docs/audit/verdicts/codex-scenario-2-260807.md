# Второй проработанный сценарий

Поставка записана в
`docs/audit/verdicts/content/scenario-2-260807.md`. Она разворачивает уже
существующую карточку `DEMO-0002` (`Musterquartier Südhang`), поэтому число
Opportunities остаётся равным восьми. `worked` меняется на `true`, а
заявленные счётчики карточки — на три здания и пять документов.

TASK-27 исправляет шесть расхождений исходной поставки, не меняя ни одной
суммы в евро. Точный срок комплекса теперь отделён от показа, входы
неприменимой формулы у project row удалены, все контроли принадлежат одному
прогону, оси формы и назначения разведены, а доли KG отделены от точных сумм.

## Чем сценарий отличается

| Признак | `DEMO-0001` | `DEMO-0002` |
|---|---|---|
| Здания | 2 | 3 |
| Назначения | Wohnen + Büro | Wohnen + Wohnen + Büro |
| Конфликты значений | 1 | 0 |
| Открытые группы покрытия | `KG_500` | `KG_500`, `KG_600` |
| Baugrundgutachten | отсутствует | присутствует |
| Активный D-02 soil risk | да | нет |
| Стартовые сдвиги исполнения | 0 / 3 | 0 / 3 / 6 месяцев |

У комплекса нет единой Leitkennzahl, объединяющей WFL и NUF. Поставка даёт
три ставки отдельных usage segments и отдельную агрегированную ставку
жилого профиля, пересчитанную от сумм двух зданий. Средние из средних нигде
не используются.

## Контроль арифметики

Денежная цепочка использует только каталог: `K_base=1.545`, `f_S=0,40`,
форму `MFH=1,00`, назначение `Büro=1,05`, классы `GK 4=1,00` и `GK 5=1,05`,
стандарты `GEG=1,00`, `EH 55=1,03`, `EH 40=1,06`, ставки UG
`1.100` / `350` и парковочную надбавку `90`. Региональный фактор выключен,
скидка и рисковые надбавки равны нулю.

Контрольный checksum:

`2.939.814,00 + 5.571.455,40 + 2.099.590,00 = 10.610.859,40 €`.

Десять строк `DEMO2-CTRL-01…10` включают четыре тотала, три ведущие ставки
сегментов, агрегированную ставку жилых сегментов от сумм, ставку комплекса
на суммарную надземную BGF и Bauzeit комплекса. Денежные показы округлены
к ближайшей `1.000 €`, ставки — к `1 €/m²`; точные значения сохранены.

Правило 39 проверяется не совпадением: ставка жилого агрегата от сумм равна
`2.287,975645… €/m²`, тогда как среднее двух building rates —
`2.319,132883… €/m²`.

## Bauzeit

Исполнение начинается после трёх месяцев планирования со сдвигами
`0 / 3 / 6`. Точные модельные длительности
`6,230000 / 9,276667 / 5,953500` округляются для показа и календарных дат до
`6,0 / 9,5 / 6,0` месяца. Во внутренний расчёт комплекса входят точные
величины:

`max(3 + 0 + 6,23; 3 + 3 + 9,276667; 3 + 6 + 5,9535) = 15,276667 Monate`.

Показ остаётся `≈ 15,5 Monate`, а максимум календарных дат задаёт Haus B с
окончанием `16.05.2029`, хотя Büro C стартует позже. Префикс согласован:
точное `15,276667` отличается от округлённого `15,5`. Строка project total
не несёт `bgfAbove`, `formFactorTime` и `classFactorTime`, потому что срок
комплекса выводится через `max(start + dauer)`, а не формулу здания.

## R-25 и provenance

`K=0`: новых множителей не введено. Единственный офисный временной
множитель `1,05` уже находится в каталоге фикстуры
`src/fixtures/catalog.json:scheduleFactors` и использован первым
сценарием; остальные значения адресованы к `calculation-spec.md` §1 и §4.
Ставки и множители перечислены отдельной машинно читаемой таблицей
`Catalog inputs`.

Baugrundgutachten — активный, успешно разобранный документ
`DEMO2-DOC-2004`; поэтому драйвер `Baugrundgutachten liegt nicht vor`
имеет `active=false` и `0,00 €`. Других рисковых надбавок поставка не
назначает.

## Оси и распределение KG

`DEMO2-B-C.gebaeudeform = null`: спецификация не даёт значения
`Gebäudeform` для нежилого объёма, и подставлять `MFH` нельзя. Назначение
`Büro` и его множитель `1,05` остаются на Usage Segment `DEMO2-S-C1`.

Coverage теперь хранит и сумму, и долю раздельно:

| Группа | `pricedAmountExact` | `allocationShare` |
|---|---:|---:|
| `KG_300` | 7.427.601,58 € | 70 % |
| `KG_400` | 2.334.389,068 € | 22 % |
| `KG_700` | 848.868,752 € | 8 % |

Сумма равна `10.610.859,40 €` точно; доля больше не маскируется под деньги.

## Идентификаторы и конфликты

Все новые сущности используют пространство `DEMO2-*`. Пересечение с ID,
именами файлов и calculation runs `DEMO-0001` пусто. Внутри сценария также
нет ни value conflict, ни version conflict: две версии Bauantrag имеют
явные состояния `active` и `superseded`, а не конкурирующие active-значения.

Все десять контрольных величин ссылаются на единственный объявленный
authoritative-прогон `DEMO2-RUN-0004`; orphan runs `0001…0003` удалены.

## Повторная проверка TASK-27

`python3 tools/check_scenario2.py` после буквальных правок печатает
**58 пройденных проверок · 7 расхождений поставки · 3 блокера интеграции**.
Пять исходных кодов исчезли: `SCH-PROJECT-EXACT`, `SCH-PREFIX-SELF`,
`SCH-PROJECT-TRAP`, `RUN-UNDECLARED`, `COV-TYPE`. Исправление project exact
снимает два исходных расхождения сразу.

Семь оставшихся сообщений имеют один механизм вне разрешённой зоны:

- `tools/check_scenario2.py:344-356` отвергает требуемый `null` как
  `AXIS-D11`, хотя TASK-27 прямо запрещает подставлять форму;
- `tools/check_scenario2.py:449-486` выводит `F_TIME_BUERO` из
  `Building.gebaeudeform`. После честного `null` это каскадом создаёт
  `SCH-FACTOR`, `SCH-EXACT`, `SCH-ROUND`, `SCH-END`, `SCH-POLICY` и
  `SCH-PREFIX` для Büro C.

Возвращать `BUERO`, подставлять `MFH` или менять корректные
`1,05 / 5,953500 / 6,0 / 01.05.2029` ради зелёной проверки нельзя: это снова
смешает `Gebäudeform` и `Nutzungsart`. Для нуля расхождений владелец
`tools/**` должен разрешить nullable form и получать офисный временной
множитель с Usage Segment. Три `ENGINE-*` блокера остаются отдельным
ожидаемым handoff в `src/**`.

## Handoff интегратору

1. `tools/check_scenario2.py:344-356,449-486` — согласовать checker с
   nullable `Gebäudeform` и segment-owned `Büro`; ожидаемый результат после
   этой внешней правки — 0 расхождений поставки.
2. `src/fixtures/opportunities.json` — для `DEMO-0002` выставить
   `worked=true`, `buildings=3`, `documents=5`.
3. Создать отдельную JSON-фикстуру из таблиц поставки без копирования
   значений `DEMO-0001`.
4. Добавить проверки `DEMO2-CTRL-01…10`; расхождение точного денежного
   значения больше `1,00 €` является release-blocker по правилу 32.
5. Completeness выводить из двух `unknown`-групп; итог обязан называться
   `Zwischensumme der kalkulierten Positionen`.
