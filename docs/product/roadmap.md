## Разворот 05.08.2026 — решение PO

Ремедиация внешнего аудита остановлена на несущей части и разложена на два реестра. Основание — измерение, а не усталость:

| | |
|---|---:|
| Документации накоплено | **18 424 строки** |
| Кода | **0** |
| Требований, закрываемых **только** на артефакте (`OBS`) | **206** |
| Требований, закрываемых **только** прогоном кода (`SPEC`) | **157** |

**363 из 394 требований (92 %) физически не закрываются без существующего продукта.** При этом артефакт стоял последним в очереди — этап 8 ремедиации. Порядок был построен наоборот: почти всё нуждалось в инструменте, а инструмент стоял в конце. Это ошибка планирования, а не свойство задачи.

Следствие было измеримым: **одиннадцать аудитов подряд, одиннадцать отклонений с первой сдачи.** Отклонения справедливы — сдавалась документация о ненаписанных экранах на приёмку по продакшн-стандарту.

**Что сделано вместо продолжения:**

- `docs/audit/prototype-gate.md` — 73 требования несущей категории. Критерий: показывает ли дефект клиенту неверное число, утекают ли реальные данные, возникает ли тупик. **Из них лишь 10 закрываются чтением документа**, остальные 63 ждут артефакта.
- `docs/audit/production-backlog.md` — 321 требование припарковано **с сохранёнными ID**. Ни одно не отменено и не переформулировано; изменилась только фаза.
- Гейт передачи привязан к этапу 7 условием, а не обещанием.
- `tools/verify.py` переносится в фазу кода без изменений и стережёт документы всё время сборки.

**Ремедиация возобновляется на этапе 5 естественно** — с настоящими экранами вместо описаний. Один аудит работающего прототипа закрывает `OBS` пачками; это принципиально дешевле девяти аудитов документации.

## Этап 5 — минимальный набор компонентов *(решение PO 05.08)*

Прототип строится на **минимальном наборе под шесть экранов** сценария Sc2 (живая встреча), а не на всех 47 доменных компонентах. Остальные контракты остаются спецификацией для ин-хаус команды.

Обоснование: прототип должен доказать **поток**, а не полноту библиотеки. Тест с sales проверяет, доводит ли продукт до отправленного оффера за встречу, — и ни один из 47 контрактов этого не проверяет, пока на него нельзя нажать.
