# Продуктовый бриф: Indicative Offer Engine

Версия 0.1 · Дата: 2026-08-04
Это корневой документ продуктовой части: идея, JTBD, сценарии. Остальные документы его детализируют.

---

## 1. Идея в одном абзаце

All3 — Timber-девелопер полного цикла на немецком рынке (проектирование → производство модулей → стройка). Продукт превращает папку клиентской документации в готовое индикативное коммерческое предложение: анализ требований, площади, стоимость по DIN 276, сроки, перечень работ, разделительная ведомость, рендеры фасадов — вместо 2–3 недель ручной работы за один день, с финальной сборкой при клиенте как частью демонстрации. Sales-менеджер остаётся ревизором и продавцом; рутина анализа, калькуляции и оформления уходит в систему.

## 2. Контекст в цифрах

| | |
|---|---|
| Средний чек проекта | ~3 млн € |
| Офферов в месяц / команда | 15–20, по одному в рабочий день |
| Sales-менеджеров | 10 |
| Конверсия оффер → контракт | ~10 % |
| Подготовка оффера сегодня | от 2–3 дней до 3 недель |
| Узкое место | **производство офферов, не поток лидов** — клиенты ждут неделями, часть уходит |

Стратегическая рамка: скорость — это не удобство, а канал выручки. Ускорение производства офферов напрямую конвертируется в объём (см. `metrics.md`, северная звезда).

## 3. Jobs to be Done

### Главный Job (sales-менеджер)

> **Когда** квалифицированный клиент передал мне документацию по проекту,
> **я хочу** превратить её в убедительное, обоснованное предложение при первом же контакте,
> **чтобы** сделка двигалась вперёд, пока клиент горяч, а я выглядел компетентнее конкурентов, которые «посчитают и пришлют через месяц».

Силы (что нанимает продукт):
- *Функционально:* прочитать сотни страниц, вытащить параметры, посчитать по DIN 276, оформить пакет документов.
- *Эмоционально:* не бояться, что в цифрах ошибка; не выглядеть новичком перед клиентом; иметь ответ на любой «а что если» прямо на встрече.
- *Социально:* эффект «они прочитали все 247 страниц за ночь и поняли мой проект» — статус в глазах клиента.

Тревоги (что мешает нанять): «а вдруг цифра неверна и я подпишусь на убыток» → интервал точности, Annahmen, источник у каждой цифры; «а вдруг я запутаюсь в интерфейсе при клиенте» → guidance-система, режим презентации.

### Job клиента (девелопер-заказчик, сидит по ту сторону экрана)

> **Когда** я рассматриваю Timber-подрядчика для своего проекта,
> **я хочу** быстро понять реальную цену, срок и границы объёма — что входит, что нет,
> **чтобы** решить, углубляться ли с этим подрядчиком, не потратив месяц на переписку.

Его тревоги — наши фичи: «скрытые исключения всплывут потом» → Leistungen + SSL прямо в пакете; «цена из воздуха» → drill-down по KG, источники, видимый Risikozuschlag за отсутствующие документы; «индикатив потом развалится» → интервал и допущения показаны честно.

### Job руководителя продаж

> **Когда** команда ведёт 20+ проектов параллельно, **я хочу** видеть очередь, статусы и качество офферов без опроса каждого менеджера, **чтобы** управлять воронкой и мощностью. *(Закрывается журналом событий и метриками; отдельный дашборд — постпрототип.)*

### Анти-Jobs — что продукт сознательно не делает

Не заменяет детальную смету (Kostenberechnung LP3+), не проектирует, не ведёт Bemusterung, не заменяет юристов (даёт заготовки), не принимает решения о скидке за sales.

## 4. Сценарии

### Sc1 — Подготовка накануне (S2, приватно, ~10 минут активной работы)

Триггер: проект пришёл из HubSpot, документы загружены, встреча завтра.
Вечером sales запускает анализ (или он уже прошёл ночью). Утром: смотрит P2 — что извлечено, с какими источниками; P3 — «эти 3 вопроса уберут 15 % неопределённости» → отправляет клиенту коротким письмом; получает пару ответов → Evidenz `bestätigt`, интервал сузился; P5 — проверяет базовый вариант, при желании готовит заготовку «Ohne UG».
**Успех:** интервал ≤ ±25 %, блокирующих вопросов нет, sales знает три главных допущения. Время подготовки — минуты, не дни.

### Sc2 — Живая встреча (S3, публично; длительность не ограничиваем)

Семь тактов:
1. **Узнавание** (глава 1): «вот что мы поняли из вашей документации» — здания, площади, стадия. Вау-момент №1.
2. **Подтверждение фактов**: клиент поправляет/называет цифры → ввод при нём → интервал сужается на глазах. Вау-момент №2 и главный механизм вовлечения.
3. **Объём** (глава 2): KG-переключатели, UG-Leistungsumfang — «что входит».
4. **Конфигурация** (главы 3–8): опции с дельта-чипами; клиент видит цену каждого решения немедленно.
5. **Вариант по запросу**: «а без паркинга?» → клон + 1 изменение, < 3 минут.
6. **Сравнение** (S4): до 4 вариантов, только различия, ★ целевой.
7. **Финал** (S5): при необходимости скидка; экспорт; отправка со встречи.
**Успех:** оффер отправлен в день встречи (северная звезда); клиент запросил ≥1 вариант (вовлечение); следующий шаг назван.

### Sc3 — Офлайн-оффер без встречи (24-часовой путь)

Не каждый клиент хочет демонстрацию. Путь: анализ → подготовка → базовый вариант + 1–2 альтернативы → экспорт → отправка письмом ≤ 24 ч от получения документов. Тот же движок, без режима презентации. **Это основной объёмный сценарий** — встреч меньше, чем офферов.

### Sc4 — Возврат: клиент дослал документы

Baugrundgutachten пришёл через неделю после отправки. Повторный анализ: `bestätigt` и Festlegungen не тронуты (M-4/D-08), новый факт ложится в Evidenz, драйвер риска «kein Baugrundgutachten» гаснет, у отправленного варианта — флаг «Grundlage geändert» с диффом. Sales жмёт «обновить» → новый снапшот → повторная отправка: «мы сняли надбавку 4 %». Цикл, который сегодня занимает дни, становится пятиминутным — и это повод для позитивного касания клиента.

### Sc5 — Первая неделя нового sales

Тур по демо-проекту (10 мин) → Übungsprojekt до уверенности → чек-лист готовности → первый реальный оффер по Sc3 (без клиента перед глазами) → первая живая встреча по Sc2. Цель: самостоятельный экспорт ≤ 1 недели (`guidance-system.md`).

## 5. Что делает продукт выигрышным — четыре механики

1. **Эффект узнавания** — первые 90 секунд встречи говорят «мы поняли ваш проект», а не «заполните форму».
2. **Сужение интервала на глазах** — каждый ответ клиента видимо повышает точность его же цены; клиент начинает *хотеть* отвечать.
3. **Видимый труд** — 247 страниц, источник у каждой цифры, страница чертежа у каждой площади: защита от «за 12 минут = угадайка» при чеке 3 млн €.
4. **Риск как счёт за документ** — Risikozuschlag поимённо: «пришлите Gutachten — снимем 4 %». Надбавка превращается в мотиватор следующего шага сделки.

## 6. Границы версий

**V1 (прототип → прод):** всё описанное в `screen-map.md`. Один пользователь на проект, без ролей и согласований.
**V2 (заявлено PO):** отправка оффера на проверку инженерам/архитекторам/конструкторам; роли и лимиты скидок; дашборд руководителя.
**Вне горизонта:** LP3+ сметы, интеграция производства, Bemusterung.
