# Карта экранов прототипа

Версия 0.1 · Дата: 2026-08-03
Связанные: `decisions.md`, `t0-fallback-rules.md`, `parameter-triage.md`

---

## 1. Общая структура

Шесть экранов. Два режима: **подготовка** (приватный) и **презентация** (клиент видит экран).

```
S1 Projektliste ──► S2 Vorbereitung ──► S3 Konfigurator ──► S5 Export
   очередь            5 вкладок            9 глав              артефакты
   действий           приватно             при клиенте
                          │                    │
                          └──► S4 Vergleich ◄──┘
                                до 4 вариантов

                      S6 Einstellungen  (скрыто от клиента, доступ из любого экрана)
```

**Правило перехода между режимами.** Переключение в презентацию — явное действие с подтверждением: «Präsentationsmodus starten». Оно скрывает всё, что клиент видеть не должен: уровни уверенности в процентах, источники в виде имён файлов, маржу, режим KG 700, драйверы риска в виде процентов. Обратный переход — тоже явный. Случайно показать клиенту внутреннюю кухню должно быть невозможно.

## 3. S2 — Vorbereitung: пять вкладок, приватно

### P1 · Dokumente
Список загруженных файлов, статус распознавания, определённая версия. Ключевой элемент — **разрешение версий**: если найдено два плана этажей, система показывает оба, выбранный помечен, с обоснованием («Datum im Plankopf 20.06.2024 gegenüber 15.11.2023»). Переключается вручную.

Повторный анализ (клиент дослал документы) **никогда не перезаписывает** значения с чипами `manuell erfasst` и `vom Kunden bestätigt` — при конфликте показывается диф, решает sales (D-08).

### P2 · Projektdaten
16 параметров T0 плюс T1, каждый с чипом источника и значением Δ.

```
┌───────────────────────────────────────────────────────────────────────────────────┐
│ GEBÄUDEKENNZAHLEN                                                      Haus A  ▾  │
├───────────────────────────────────────────────────────────────────────────────────┤
│ BGF oberirdisch               1.969,67 m²   ◆ aus Dokument · S. 15         ✎      │
│ BGF unterirdisch                328,28 m²   ◆ aus Dokument · S. 7          ✎      │
│ BGF S (nicht umschlossen)         0,00 m²   ◆ aus Dokument                 ✎      │
│ Wohnfläche WFL nach WoFlV     1.240,39 m²   ◆ aus Dokument · Bl. 17        ✎      │
│   Balkon-Anrechnung                  25 %   ◆ WoFlV §4                            │
│ Wohneinheiten                          15   ◆ aus Dokument                 ✎      │
│ Gebäudeklasse                        GK 5   ▲ Prüfung erforderlich         ✎ ±3 % │
│                                               Prüfauslöser: 5 Vollgeschosse       │
│ Energiestandard                     EH 55   ◆ Projektabstimmung            ✎      │
└───────────────────────────────────────────────────────────────────────────────────┘
```

Треугольник = подставлено системой, ромб = извлечено или подтверждено. Значения Δ показываются **только здесь**, в презентацию не попадают.

### P3 · Offene Fragen
Список вопросов клиенту, **отсортированный по величине Δ**, а не по порядку параметров. Две группы: блокирующие и уточняющие. Кнопка экспорта списка — чтобы отправить клиенту накануне.

```
│ 1. Welcher Effizienzhaus-Standard ist vorgesehen?         −4 % │
│ 2. Liegt eine Wohnflächenberechnung nach WoFlV vor?       −5 % │
│ 3. Ist ein Baugrundgutachten vorhanden?           Risiko −x %  │
```

Заголовок блока: «Diese 3 Fragen reduzieren die Unschärfe von ±22 % auf ±13 %». Это превращает подготовку в десятиминутную задачу вместо часовой.

### P4 · Annahmen
Все сработавшие подстановки с готовым немецким текстом из `t0-fallback-rules.md`. Каждое допущение можно снять, введя значение.

### P5 · Varianten
Список вариантов проекта. Создание, клонирование, пометка целевого, переход в конфигуратор.

Двухпанельный. Слева главы, справа живой оффер. **Цена видна всегда.**

```
│ │ [ 1.240,39 ] m²   ◆ aus Dokument       │ │               295.000 €         8 %        │
│ │   Balkone: (•) 25 %   ( ) 50 %         │ │                                            │
│ │                                        │ │   ▸ Detaillierung KG 300                   │

│   3 übernommene Änderungen · aufklappen für Einzelposten                                │

```

> *Уточнение после дизайн-системы (DC-38, D-15):* числа правой панели в мокапе — вайрфреймные. Реальная иерархия: **три со-главных героя** — Gesamt (64, оранжевый), Leitkennzahl по типу (48, чёрный; для Berlin без регионального фактора: 3.682.000 € и ≈ 2.968 €/m² WFL nach WoFlV — вайрфреймные 3.847.000/1.987 не бились ни с WFL nach WoFlV, ни с D-15), Bauzeit (48). €/m² BGF oberirdisch и € je WE — вторичная строка. Точные значения — фикстуры по `calculation-spec.md`.

**Механики, которые обязательны:**

- **Поля ввода прямо в презентации.** Все числовые T0 редактируются здесь же (D-08). Клиент называет площадь — sales вводит, всё пересчитывается мгновенно, чип источника меняется на `vom Kunden bestätigt`, доверительный интервал **сужается на глазах** с анимацией. Это самый сильный момент демонстрации.
- **Дельта-чип.** При переключении опции рядом с ценой на 4 секунды появляется `Energiestandard EH 55 → EH 40 · + 96.000 € (+ 2,6 %)`, затем уезжает в журнал.
- **Журнал изменений сессии** — свёрнутая полоса внизу. Разворачивается в список. Sales в любой момент говорит: «мы поменяли вот эти три вещи».
- **Никаких аккордеонов глубже одного уровня.** Глава открыта целиком или закрыта. Если параметров больше двенадцати — глава делится, а не сворачивается внутрь себя.
- **Прыгать можно куда угодно.** Нумерация глав — рекомендованный маршрут, а не принуждение. Клиент спрашивает про паркинг на третьем шаге — открываем главу 2, цена не теряется.

Режим `KG-700-Modus` здесь **не показывается** — он в S6, скрыт от клиента. Мокап отражает состояние Referenzprojekt R-01: KG 200 включена автоматически, потому что `Abbruch = ja` (правило V10). **Комплекс зданий (D-14).** При `Anzahl Gebäude > 1` в шапке рабочей области появляется переключатель охвата `Gesamt · Haus A · Haus B` (DC-46) — он меняет охват всей страницы, а не только одной панели. Разделение по уровням:

| Главы уровня `gebäude` — переключатель активен | Главы уровня `projekt` — переключатель скрыт |
|---|---|
| 3 Gebäude & Flächen · 4 Energie & Qualität · 5 Konstruktion & Fassade · 6 Ausbau & Technik | 2 Umfang · 7 Baugrund & Erschließung · 8 Leistungsabgrenzung · 9 Termine & Kommerzielles |
| у каждого здания свой тип (D-11), свои площади, свой Leitkennzahl | помечены «gilt für den gesamten Komplex» |

При охвате `Gesamt` вместо параметров главы 3 показывается **Komplex-Übersicht** (DC-47): строка на здание + итог, ниже — сегментные подытоги Wohnen/Büro. Отдельного обзорного экрана нет.

**Классификация задаётся четырьмя контролами (D-11 v2, R-13):** `Gebäudeform` — на уровне здания; `Nutzungsart`, `Belegungsprofil`, `Benchmarkprofil` — на уровне сегмента использования. В охвате `Gesamt` классификация read-only. Смешанное использование — это `2..n` сегментов внутри здания, а не отдельный тип.

## 5. S4 — Variantenvergleich

До четырёх вариантов. **По умолчанию показываются только строки с различиями**, переключатель «alle Zeilen anzeigen» рядом. Полная таблица на 25 строк с четырьмя одинаковыми колонками нечитаема.

Роли колонок независимы (VARIANT-001, XSC-08): целевой вариант помечен ★, а дельты считаются к колонке-`Vergleichsbasis` (здесь `Basis`) — поэтому строка дельты названа явно.

**Точная копия по контексту (VARIANT-010, COPY-006).** Три разных места — три разных текста, и подменять их друг другом нельзя:

| Контекст | Точный текст |
|---|---|
| имя варианта | `Ohne UG` |
| строка сравнения | `Untergeschoss: nicht Bestandteil` |
| scope-detail (Leistungen, SSL, PDF) | `UG nicht Bestandteil des All3-Leistungsumfangs` |

Слово `keins` запрещено во всех трёх контекстах; `kein UG` — не текст интерфейса, а машинное состояние `kein_ug`.

**Одна дельта на один Impact Context (CALC-012, XSC-20).** Значения мокапа принадлежат вайрфрейму Referenzprojekt R-01 с базой `3.682.000 €`: `Ohne UG` = `− 391.000 €` (`328,28 m² × 1.190 €/m²`), `EH 40` = `+ 96.000 €`. Превью изменения, дельта-чип, журнал сессии и эта таблица показывают **одно и то же** число для одного Impact Context. Синтетическая фикстура (`synthetic-fixtures.md`, `DEMO-IMP-0004`) — **другой** Impact Context со своей базой `3.818.000 €` и дельтой `− 476.000 €`; смешивать значения двух контекстов запрещено.

## 9. Guidance-слой

Поверх всех экранов живёт guidance-система (спецификация — `guidance-system.md`): термин-тултипы из единого глоссария, затухающие контекстные подсказки, превью последствий перед рискованными действиями (G1–G21), обучающие лоадеры, онбординг-тур по демо-проекту и Übungsprojekt. Правило режима: в Präsentationsmodus коучинг выключен, предупреждения свёрнуты до нейтральных иконок. **В прототипе guidance-слой обязателен** — тест с sales проверяет в том числе его: каждый случай, когда модератор объясняет голосом, — недостающая подсказка.

## 10. Что прототип сознательно не делает

Не подключает LLM · не парсит реальные PDF (симуляция таймерами с реалистичной длительностью) · не пишет в HubSpot · не генерирует документы, кроме презентации · не генерирует рендеры (библиотека готовых изображений на трёх демо-проектах) · не имеет ролей и авторизации, кроме пароля на URL.
